# ADRs

Architecture Decision Records preserve accepted technical and software-architecture choices.

## What Belongs Here

Technical decisions about implementation structure, interfaces, infrastructure, dependencies, data architecture, or deployment.

## What Does Not Belong Here

Institutional policy, cross-system governance, undecided proposals, system specifications, or Canon synthesis.

## How Documents Enter

A reviewed technical proposal becomes an ADR when its architecture owners explicitly accept the decision.

## How Documents Leave or Become Superseded

ADRs are never silently removed. A replacement ADR links both records and preserves consequences and migration context.

## Decision Boundary

Use `../decisions/` for institutional and cross-system decisions. An ADR may implement a `DEC-*` decision and should link it.

## Related Folders

- `../rfcs/` contains proposals.
- `../decisions/` contains institutional decisions.
- `../systems/` contains current specifications.
- `../archive/` preserves retired supporting material.
